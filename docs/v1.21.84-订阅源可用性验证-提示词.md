# 提示词：验证「喵公子」订阅源（RSS）是否可用

> 用途：交给 AI 会话/编码代理，**独立判断**这个订阅源能不能用
> 目标源：`http://yuedu.miaogongzi.net/shuyuan/miaogongziDY.json`
> 入口页：`https://dy.mgz6.com/` → 按钮「喵公子订阅源」
> 结论必须**有证据**，不能靠猜

---

## 零、任务定义

用户想接入这个订阅源。你要回答**三个问题**，每个都要给证据：

| # | 问题 | 判定标准 |
| --- | --- | --- |
| Q1 | 这份 RSS JSON **本身**是否合法、字段是否齐全？ | 能解析、必需字段非空 |
| Q2 | 它指向的**列表页**是否还符合 `ruleArticles` 的假设？ | 选择器能否匹配到元素 |
| Q3 | 如果失效，**是站点改版还是源写错**？能不能修？ | 给出新选择器并验证 |

⚠️ **不要**只回答「能导入」就结束。能导入 ≠ 能用。

## 一、已有证据（供你复核，不要直接采信）

以下是上一轮抓取的**原始观测**，你可以复现也可以推翻：

### 1.1 RSS JSON 本身

```bash
curl -s -k -L "http://yuedu.miaogongzi.net/shuyuan/miaogongziDY.json"
```

- HTTP 200，**11020 字节**，`application/json`
- 顶层是**数组**，**1 条**
- 关键字段：

```
sourceName  = 喵公子书源管理
sourceUrl   = http://yuedu.miaogongzi.net/gx.html
sourceGroup = 书源
type        = 0
ruleArticles= id.content@h3
ruleLink    = a@href
ruleTitle   = a@textNodes
singleUrl   = true
loadWithBaseUrl = true
lastUpdateTime  = 1675946926480   ← 2023-02
```

### 1.2 它指向的列表页

```bash
curl -s -k -L "http://yuedu.miaogongzi.net/gx.html"
```

- HTTP 200，**11701 字节**
- **实测计数**：

| 特征 | 出现次数 |
| --- | --- |
| `<h3` | **0** |
| `id="content"` | **0** |
| `class="aui-flex b-line"` | **26** |
| `class="aui-flex-box"` | **27** |
| `booksource/importonline` | **11** |

**结论**：`ruleArticles = "id.content@h3"` 在这个页面上**匹配数为 0**。

### 1.3 页面的真实结构

```html
<div type="" about="" class="aui-flex b-line">
  <div class="aui-flex-box">
    <h1>阅读出大事了！！！！请尽快查看</h1>
  </div>
  <a href="https://www.bilibili.com/opus/1048239278905098277">
    <div class="aui-film-button"><button>点击前往</button></div>
  </a>
</div>
```

也就是说：**容器是 `div.aui-flex.b-line`，标题在 `h1`，链接在 `a`** ——
和 `h3` 完全对不上。

## 二、你要做的验证（按顺序）

### V1. 复现抓取

```powershell
# Windows / PowerShell
curl.exe -s -k -L --max-time 30 -A "Mozilla/5.0" -o "$env:TEMP\rss.json" `
  "http://yuedu.miaogongzi.net/shuyuan/miaogongziDY.json"

curl.exe -s -k -L --max-time 30 -A "Mozilla/5.0" -o "$env:TEMP\gx.html" `
  "http://yuedu.miaogongzi.net/gx.html"
```

记录：**HTTP 状态码、字节数、Content-Type**。

⚠️ 注意 `-k`：这个站点证书链有问题（`Invoke-WebRequest` 会报
`未能为 SSL/TLS 安全通道建立信任关系`）。但**应用里不能跳过证书校验** ——
如果正式请求失败，这本身就是「不可用」的一条理由。

### V2. 校验 JSON 字段

对照 legado 的 `RssSource` 必需字段：

| 字段 | 是否必需 | 说明 |
| --- | --- | --- |
| `sourceUrl` | ✅ | 主键 |
| `sourceName` | ✅ | |
| `ruleArticles` | ✅ | 文章列表容器选择器 |
| `ruleLink` | ✅ | 文章链接 |
| `ruleTitle` | ✅ | 文章标题 |
| `type` / `enabled` / `sortUrl` / `header` | 可选 | |

**输出**：字段齐全度表，缺哪个标出来。

### V3. 用现有规则引擎试算（**关键**）

项目里已经有规则引擎，**直接用它**，不要另写：

```dart
// 在 test/ 下建一个临时验证用例
final RuleEngine engine = RuleEngine(
  content: gxHtml,
  kind: ContentKind.html,
  context: RuleContext(baseUrl: 'http://yuedu.miaogongzi.net/gx.html'),
);

// 容器
final List<Object?> items = engine.getElements('id.content@h3');
print('容器数: ${items.length}');

// 逐个取链接与标题
for (final Object? it in items) {
  final RuleEngine e = RuleEngine(
    content: it.toString(),
    kind: ContentKind.html,
    context: RuleContext(baseUrl: '...'),
  );
  print('${e.getString('a@textNodes')} -> ${e.getString('a@href')}');
}
```

**预期**：`容器数 = 0`（即证明确实失效）。

如果结果不是 0，说明上一轮的观测有误，**以你的实测为准**并说明差异。

### V4. 判断失效原因

| 可能 | 判据 | 结论 |
| --- | --- | --- |
| 站点改版 | 页面结构变了（`h3` → `h1` + `div.aui-flex`） | **源需重写**，但站点活着 |
| 源本身写错 | 从没匹配过 | 源质量问题 |
| 站点已死 | HTTP 非 200 / 超时 / 域名失效 | **彻底不可用** |
| 反爬 | 返回验证码页 / 空壳 | 需特殊处理 |

**本次证据指向**：站点活着（200，有内容），但**结构改了** → 源需重写。

### V5. 尝试修复（如果 V4 判为「改版」）

用真实结构重写选择器：

```
ruleArticles = class.aui-flex b-line     ← 26 个容器
ruleTitle    = tag.h1@text               ← 标题在 h1
ruleLink     = tag.a@href                ← 链接在 a
```

⚠️ **注意**：这 26 个容器里**不全是书源**，混着公告、B站推广、公众号等。
真正含 `booksource/importonline` 的只有 **11 个**。

**验证要求**：用新选择器跑一遍，回答：

- 取到多少容器？
- 其中多少个**真的**是书源链接？
- 有多少是噪音（公告/推广）？
- 标题是否合理？

**如果噪音占比很高**，说明这个页面**不适合当 RSS 源** —— 它是个「导航页」，
不是「文章列表页」。

## 三、必须回答的最终问题

### Q1：这份 RSS JSON 合法吗？

（字段齐全度、是否含非法内容）

### Q2：`ruleArticles` 能匹配到东西吗？

（给出实测数字，不要「应该能」）

### Q3：如果不能，能不能修？

| 情况 | 结论 | 建议 |
| --- | --- | --- |
| 改版可修 | 给出新选择器 + 实测结果 | 值得做 |
| 改版但噪音高 | 给出噪音比例 | **不建议**，另找源 |
| 站点已死 | 给出证据 | 不可用 |
| 反爬 | 给出响应特征 | 需特殊处理 |

### Q4：**这个源值不值得支持？**

判断依据（至少回答 2 条）：

- 内容质量：抓到的 11 个链接里，有多少是**书源合集**（而非推广）？
- 更新频率：`lastUpdateTime` 是 2023-02，**三年没更新**
- 可替代性：这些书源是否在别处也能拿到？

## 四、额外要求：**找一个对照样本**

⚠️ **只用这个失效源，你无法证明「RSS 功能本身写得对」**。

请**自己造一份最小可用的 RSS 源 + 静态 HTML**：

```html
<!-- 本地测试页 -->
<div id="list">
  <div class="item"><a href="/a/1">文章一</a></div>
  <div class="item"><a href="/a/2">文章二</a></div>
</div>
```

```json
[{
  "sourceUrl": "http://localhost/list.html",
  "sourceName": "测试源",
  "ruleArticles": "id.list@class.item",
  "ruleLink": "tag.a@href",
  "ruleTitle": "tag.a@text"
}]
```

用它验证：

1. 能解析出 **2** 个容器
2. 标题是「文章一」「文章二」
3. 相对链接 `/a/1` 能补成绝对地址

**这一条通过 = RSS 功能可用；真实源失效是另一件事。**

### 5.4 建议

- 能用 → 怎么接

## 六、不要做的事

| ❌ | 原因 |
| --- | --- |
| 只看 JSON 就说「能用」 | 能导入 ≠ 能抓到内容 |
| 拿失效源当「功能写错」的证据 | 会误导后续开发 |
| 用 `Invoke-WebRequest` 不加 `-k` | 该站证书链有问题，会失败 |
| 修改 `lib/` 下的代码 | **本任务是验证，不是实现** |
| 只测真实源、不造对照样本 | 无法区分「功能错」与「源失效」 |

⚠️ **本任务默认只读**。如果确实需要写测试用例，放在 `test/` 下，
命名以 `_diag_` 开头，**完成后删除**。
