## 一、A：一键导入（`yuedu://` 链接自动识别）

### A.1 目标

用户在内置浏览器里点 `yuedu://booksource/importonline?src=<URL>` 时，
**自动拦下、提取 `src`、走现有导入流程**，而不是显示「打不开」。

### A.2 现状（已核实）

`lib/pages/browser_page.dart` 的 `shouldOverrideUrlLoading`（**L2326**）已经有一套
scheme 拦截逻辑：

```dart
if (scheme == 'intent' || scheme == 'market' || scheme == 'tg' ||
    scheme == 'weixin' || scheme == 'alipays') {
  // 提示 + CANCEL
  return NavigationActionPolicy.CANCEL;
}
```

**没有** `yuedu` / `legado` 分支。

### A.3 需要支持的链接形态

```
yuedu://booksource/importonline?src=<url>       ← 书源（本次要做）
yuedu://bookSource/importonline?src=<url>       ← 大小写变体，legado 两种都认
legado://import/bookSource?src=<url>            ← 另一套 scheme（legado 新版）
legado://import/importonline?src=<url>&type=booksource
```

⚠️ **大小写不敏感**：legado 的 path 有 `/bookSource` 和 `/booksource` 两种写法。

### A.4 实现要求

#### 1. 新建解析器

`lib/services/source_link_parser.dart`

```dart
/// 从 yuedu:// / legado:// 链接里提取书源地址
class SourceLinkParser {
  /// 解析结果：null 表示不是书源导入链接
  static String? extractBookSourceUrl(String link);

  /// 是不是「书源导入」链接（用于 UI 提示）
  static bool isBookSourceLink(String link);
}
```

要求：

- 支持 `yuedu` / `legado` 两个 scheme
- path 大小写不敏感（`/bookSource` == `/booksource`）
- 只认 `booksource` / `importonline` 两类 path
- `src` 参数要**做 URL 解码**（真实链接里 `src` 常含 `%E4%B8%AD` 这种编码）
- 非法/缺 `src` 返回 null
- **纯函数，零依赖，必须能离线单测**

#### 2. 接到浏览器拦截

在 `shouldOverrideUrlLoading` 里，**在现有 intent/market 分支之前**加：

```dart
if (SourceLinkParser.isBookSourceLink(target)) {
  final String? src = SourceLinkParser.extractBookSourceUrl(target);
  if (src != null) {
    // 提示用户 + 跳转到导入
    // 返回 CANCEL
  }
}
```

⚠️ **交互要求**：不要静默导入。弹一个确认对话框：

```
┌────────────────────────────────┐
│ 发现书源                       │
│ 这个链接包含一份书源，要导入吗？ │
│ <src 地址，可滚动>              │
│        [取消]  [导入]           │
└────────────────────────────────┘
```

用户点「导入」→ 走 `SourceImporter.parse(src)` → 走现有的合并/入库逻辑。

⚠️ **复用而非重写**：`lib/pages/legado_sources_page.dart` 里的 `_importText()` 已经是完整流程
（解析 → 合并 → 写库 → 结果对话框）。**把它抽成可复用的函数**，不要复制一份。

建议抽到 `lib/services/source_import_flow.dart`：

```dart
/// 导入一段文本/地址，返回可直接展示的结果摘要
Future<SourceImportSummary> importSourcesFromInput(String input);
```

#### 3. 粘贴也支持

用户可能直接**粘贴** `yuedu://...` 到「导入」输入框。
`SourceImporter.parse()` 目前只认 `http(s)` / `file` / `content` / 纯 JSON。

**要求**：在 `SourceImporter._resolveInput` 里，先试 `SourceLinkParser`：

```dart
// 伪代码
final String? fromLink = SourceLinkParser.extractBookSourceUrl(trimmed);
if (fromLink != null) return _resolveInput(fromLink, ...);
```

这样「粘贴链接」和「浏览器点击」两条路都能用。

### A.5 验收

| # | 用例 |
|---|---|
| 1 | `yuedu://booksource/importonline?src=https%3A%2F%2Fa.com%2Fb.json` → 提取出 `https://a.com/b.json` |
| 2 | `legado://import/bookSource?src=http://x.com/y.json` → 提取成功 |
| 3 | 大小写变体 `/bookSource` 与 `/booksource` 都能认 |
| 4 | 缺 `src` → 返回 null，不崩 |
| 5 | `yuedu://rsssource/...` → **不**被当成书源（返回 null） |
| 6 | 普通 `https://` 链接 → 返回 null，浏览器正常导航 |
| 7 | 浏览器里点真实链接 → 弹确认框 → 导入成功 |
| 8 | 粘贴到导入框 → 导入成功 |

### A.6 工作量

**约 150~200 行 + 10 个用例**，半天。

## 二、B：订阅源（RSS）

### B.1 先想清楚：这是另一套体系

**RSS 源 ≠ 书源。** 两者字段、语义、用途完全不同：

| | 书源 `BookSource` | 订阅源 `RssSource` |
| --- | --- | --- |
| 用途 | 搜书 → 目录 → 正文 | 追更：一个站点/频道的最新文章列表 |
| 核心规则 | `ruleSearch` / `ruleToc` / `ruleContent` | `ruleArticles` / `ruleLink` / `ruleTitle` |
| 阅读单位 | 章节 | 文章 |
| 本工程状态 | ✅ 已实现 | ❌ **完全没有** |

⚠️ **不要试图把 RSS 源塞进 `SourceRule`**。字段对不上，会污染现有模型。

### B.2 真实 RSS 源长什么样（已抓取）

`http://yuedu.miaogongzi.net/shuyuan/miaogongziDY.json`：

```json
[{
  "sourceName": "喵公子书源管理",
  "sourceUrl": "http://yuedu.miaogongzi.net/gx.html",
  "sourceGroup": "书源",
  "sourceIcon": "data:image/png;base64,...",
  "type": 0,
  "enabled": true,
  "enabledCookieJar": false,
  "lastUpdateTime": 1675946926480,
  "customOrder": 3,
  "sortUrl": "首页::http://yuedu.miaogongzi.net/gx.html",
  "ruleArticles": "id.content@h3",
  "ruleLink": "a@href",
  "ruleTitle": "a@textNodes",
  "singleUrl": true,
  "loadWithBaseUrl": true,
  "preload": false,
  "articleStyle": 0,
  "enableJs": true,
  "showWebLog": false,
  "header": "{\"User-Agent\":\"Mozilla/5.0 ...\"}"
}]
```

### B.3 字段语义（必须对齐）

| 字段 | 含义 |
| --- | --- |
| `sourceUrl` | **主键**（列表页地址） |
| `sourceName` | 名称 |
| `sourceGroup` | 分组 |
| `sourceIcon` | 图标（base64 data URI 或 URL） |
| `type` | 0 = 文本 |
| `ruleArticles` | **文章列表容器**的选择器（返回 N 个元素，每个是一篇文章的容器） |
| `ruleLink` | 在容器内取**文章链接**（相对地址，需按 `sourceUrl` 补全） |
| `ruleTitle` | 在容器内取**标题** |
| `sortUrl` | 分类/排序入口，格式 `名称::URL`，多个用 `\n` 或 `&&` 分隔 |
| `singleUrl` | true = 只有一页，不分页 |
| `loadWithBaseUrl` | true = 请求时带 `sourceUrl` 作为 base |
| `preload` | 是否预加载正文 |
| `articleStyle` | 正文样式（0 = 默认） |
| `header` | 请求头 JSON 字符串 |

### B.4 关键难点：`ruleArticles` 的语义

`ruleArticles = "id.content@h3"` 意思是：

1. 找到 `id="content"` 的元素
2. 在它内部找所有 `<h3>` —— **每个 `<h3>` 是一篇文章的容器**
3. 然后在**每个 h3 内部**，用 `ruleLink`（`a@href`）取链接、`ruleTitle`（`a@textNodes`）取标题

⚠️ **这和书源的 `bookList` 语义一样**：先取 N 个容器，再在容器内取字段。
你已有的 `RuleEngine.getElements()` 正是干这个的（见 `source_client.dart` 的 `_extractItemHtml`）。

**所以 RSS 可以复用现有规则引擎**，只是换一套字段名和流程。

### B.5 ⚠️ 实测警告：这个特定源可能已经失效

我抓了 `gx.html`（11701 字节），**里面没有 `id="content"`，也没有 `<h3>`**：

```
实际结构：section.aui-flexView > section.aui-scrollView > div.tab-panel > div.aui-flex.b-line ...
```

也就是说 `ruleArticles = "id.content@h3"` **匹配不到任何东西** —— 这个源大概率已随站点改版失效
（`lastUpdateTime = 1675946926480` = 2023-02）。

**这不是你的 bug**。但意味着：

1. **不要拿这个源当验收标准**，它会「正确解析但零结果」
2. 实现时要能**明确区分**「源失效（零结果）」和「解析出错」
3. 建议找一个**活的** RSS 源做验收（可以自己建一个静态 HTML 测）

### B.6 实现范围（建议分两期）

#### 一期：能导入 + 能列出文章（**必须**）

```
lib/models/rss_source.dart            RssSource 模型（字段对齐 legado）
lib/services/rss_importer.dart        导入解析（三形态，同 SourceImporter）
lib/services/rss_store.dart           持久化（新键 rss_sources_v1）
lib/services/rss_client.dart          抓列表页 → 解析文章列表
lib/pages/rss_sources_page.dart       源管理（导入/启停/删除）
lib/pages/rss_articles_page.dart      某源的文章列表
```

**不做**：正文抓取、订阅更新提醒、未读标记。

#### 二期（可选，后续再做）

- 文章正文抓取（需要 `ruleContent`，RSS 源里通常没有，得靠通用正文抽取）
- 定时刷新 + 新文章提醒
- 未读/已读状态

### B.7 复用清单（**别重写**）

| 已有能力 | 位置 | 怎么用 |
| --- | --- | --- |
| 规则求值 | `services/rule_engine.dart` | 直接 `RuleEngine(...).getElements()` / `getStringList()` |
| URL 补全 | `services/url_template.dart` | 相对地址 → 绝对地址 |
| HTTP + 编码 | `services/url_template.dart` 的 `SourceHttpClient` | 含 GBK 钩子 |
| 三形态解析骨架 | `services/source_importer.dart` | **抄结构**，不要 import（模型不同） |
| 导入 UI 流程 | `pages/legado_sources_page.dart` | 抽公共部分复用 |

⚠️ **`RuleEngine` 的 `ContentKind` 判断**：RSS 列表页是 HTML，直接传 `ContentKind.html`。

### B.8 验收

| # | 用例 |
|---|---|
| 1 | 解析真实 RSS JSON（上面那份）→ 1 条，字段全对 |
| 2 | `ruleArticles` 为 `id.content@h3` 时，能取出 N 个 h3 容器 |
| 3 | 在容器内用 `ruleLink` / `ruleTitle` 取到链接与标题 |
| 4 | 相对链接 `/a/1` 能按 `sourceUrl` 补成绝对地址 |
| 5 | 列表页零匹配 → 明确报「源可能已失效」，**不是**崩或空列表干瞪眼 |
| 6 | 导入后能在列表里看到、能启停、能删 |
| 7 | 点源能进文章列表页 |
| 8 | **用一份自己造的正常 HTML 验证全链路**（不依赖那个失效的真实源） |

### B.9 工作量

**一期约 3~4 天**，二期另算。

## 四、必须避免的坑

| 坑 | 说明 |
| --- | --- |
| **把 RSS 塞进 `SourceRule`** | 字段对不上，会污染现有模型和测试 |
| **复制 `_importText` 而不抽公共函数** | 两份导入逻辑必然漂移（项目里已经因此出过事） |
| **用那个失效的真实源做验收** | 它会「成功但零结果」，让你误以为解析写错了 |
| **静默导入** | 浏览器里点链接必须弹确认，不能直接改用户的书源库 |
| **忘记 URL 解码** | `src` 里常含 `%E4%B8%AD` 这类编码，不解码会 404 |
| **大小写敏感** | `/bookSource` 与 `/booksource` 都要认 |
| **PowerShell 回写 .dart** | 会压行、坏编码，项目里出过两次事故 |
