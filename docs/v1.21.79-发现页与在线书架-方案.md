## 三、页面结构设计

### 3.1 导航栏：三 Tab → 四 Tab

```
文档库    发现    浏览器    设置
 ↓        ↓       ↓        ↓
library  discover browser  settings
```

⚠️ **顺序**：用户说「导航栏新增发现页」，未指定位置。建议**放在文档库之后**，
因为它是内容入口（找书），浏览器是工具入口。

⚠️ **影响面**：`_index` 是硬编码数字（`0` = 文档库、`1` = 浏览器、`2` = 设置），
新增 Tab 会**平移所有索引**。必须逐一检查：

- `_visited` 集合（懒建页面的标记）
- `IndexedStack` 的 children 顺序
- `_index == 1 ? progressBarHeight : 0`（浏览器进度条）
- `_index == 0` 的两处（AppBar actions、FAB）
- 宽屏 `NavigationRail` 与 `NavigationBar` **两处** destinations

> **建议**：改成具名常量（`_kLibrary = 0` / `_kDiscover = 1` / `_kBrowser = 2` / `_kSettings = 3`），
> 避免以后再加 Tab 时再数一遍。

### 3.2 发现页布局

```
┌──────────────────────────────────────┐
│ 发现                          🔍  ⋮  │  ← 🔍 改为「导入」，⋮ 展开书源勾选
│ 全部                                  │
│ ┌──────────────────────────────────┐ │
│ │ 🔍 搜索书名 / 作者                │ │  ← 搜书源（不是搜本地）
│ └──────────────────────────────────┘ │
│ ┌──────────────────────────────────┐ │
│ │ ⬇ 下载列表                    (3) │ │  ← 与浏览器同款 DownloadsSheet
│ └──────────────────────────────────┘ │
│                                      │
│ （下面是搜索结果 / 空态引导）          │
└──────────────────────────────────────┘
```

**「右上放大镜替换为导入键」的理解**：截图里 🔍 是搜索按钮。用户要求换成**导入**（导入书源），
因为搜索已经由页面内的搜索框承担。

**三点（⋮）展开**：书源勾选列表（多选），勾上 = 启用，取消 = 禁用。

### 3.3 文档库：搜索栏下方加书架

```
┌──────────────────────────────────────┐
│ [ 搜索书名或文件名        ]  [＋]     │
├──────────────────────────────────────┤
│ 本地书架 (12)                    展开 │  ← 在前
│ · 三体.pdf                           │
│ · 鬼吹灯.epub                        │
├──────────────────────────────────────┤
│ 在线书架 (3)                     展开 │  ← 在后
│ · 某书 · 第 42 章 · 来自 XX 源       │
├──────────────────────────────────────┤
│ （原有文档列表 / 网格）                │
└──────────────────────────────────────┘
```

⚠️ **这里的取舍要想清楚**：现在文档库是「整页列表」，加两个书架后会有**三段内容**。
建议书架做成**可折叠的两个横条**（默认展开本地、折叠在线），
避免占用太多竖向空间。或者做成横向滚动卡片。

> 具体形态建议在实现时拿截图确认，本文档只定「本地在前、在线在后」的硬要求。

## 四、核心流程：搜书 → 简介 → 三键

### 4.1 流程图

```
发现页搜索框输入关键词
   ↓
读出「已启用」的书源（load() 中 enabled && isSupported）
   ↓
多源并发搜索（复用 LegadoSearchPage 的并发写法）
   ↓
结果列表（书名 / 作者 / 来源书源）
   ↓ 点一本
┌─────────────────────────────────────┐
│ 简介页                              │
│  封面 · 书名 · 作者                 │
│  简介正文                            │
│  ─────────────────────────────────  │
│  [下载]   [加入书架]   [阅读]        │
└─────────────────────────────────────┘
```

### 4.2 三个按钮的语义（**必须先定死，否则实现会跑偏**）

| 按钮 | 行为 | 产物 |
| --- | --- | --- |
| **下载** | 拉全部章节正文 → 拼成 TXT → `LibraryStorage.adopt` → `upsertDocument` | **本地文档库多一本**（可离线朗读） |
| **加入书架** | 写 `OnlineBookRecord`（不抓正文） | 在线书架多一条（点进去按需抓） |
| **阅读** | 直接进 `LegadoReadPage`，按窗抓正文 | 不落盘，读完进度记到 `OnlineBookRecord` |

> ⚠️ **「下载」和「加入书架」是两件事**，不要合并：
> - 下载 = 离线化（占空间、耗时长、可脱网）
> - 加入书架 = 收藏（几乎零成本，联网才可读）
>
> 用户在三个按钮上做的选择，本质是在选「要不要现在就付下载代价」。

### 4.3 简介页需要什么数据

`OnlineBook` 现有字段：`name` / `url` / `author` / `coverUrl` / `intro` / `lastChapter` / `kind`。

⚠️ **`intro` 通常来自 `ruleBookInfo.intro`，需要额外请求详情页**。
搜索结果的 `ruleSearch` 里一般**没有**简介。

所以简介页要做：
1. 先用搜索结果里已有的字段渲染（书名/作者/封面）
2. **异步补一次详情页**（`ruleBookInfo` 的 `name`/`intro`/`coverUrl`）
3. 补失败就只显示已有字段（不阻塞三键）

> 这需要一个新方法：`SourceClient.bookInfo(bookUrl)`。
> 现有 `toc()` 里已经请求过详情页但只取了 `tocUrl`，需要抽出复用。

## 五、下载实现：这是本轮最重的部分

### 5.1 关键约束

「下载」要拉**全部章节**，但：

- 一部书可能 **几千章**
- 每章一次 HTTP 请求
- 必须能**后台进行 + 显示进度 + 可取消**
- 下载完要**自动进本地书库**（需求 3）

### 5.2 三种实现路径

| 路径 | 做法 | 优点 | 缺点 |
| --- | --- | --- | --- |
| **A. 复用 flutter_downloader** | 把每章当一个下载任务 | 直接有下载列表 UI | ❌ 它是**文件下载**，不是「请求+解析」，规则引擎用不上 |
| **B. 自建下载队列 + 复用 DownloadsSheet 展示** | 自己管并发/进度，把状态映射成 `DownloadTask` 形状 | 可控、能显示在同款列表里 | 需要适配层 |
| **C. 只做「前台下载 + 进度条」** | 在简介页弹进度对话框，不接系统下载列表 | 最简单 | 不满足需求 3「加到下载列表」 |

**建议 B**：需求 3 明确要求「下载列表按钮和浏览器的一样」，
说明用户希望**统一的下载视图**。

### 5.3 路径 B 的适配层设计

`DownloadsSheet` 吃的是 `List<DownloadTask>`（flutter_downloader 的类型）。
两个选择：

**B1. 造 `DownloadTask` 对象**（不推荐）
- `DownloadTask` 是插件的类，字段可能不可写
- 语义混淆：那不是真的文件下载任务

**B2. 抽象一层「下载条目」**（推荐）

```dart
// lib/models/online_download.dart
enum OnlineDownloadState { queued, running, done, failed, canceled }

class OnlineDownload {
  final String bookUrl;
  final String bookName;
  final String sourceUrl;
  int doneChapters;
  int totalChapters;
  OnlineDownloadState state;
  String? error;
  double get progress => totalChapters == 0 ? 0 : doneChapters / totalChapters;
}
```

然后**把 `DownloadsSheet` 泛化**：抽出一个 `DownloadItemView` 接口，
让浏览器的 `DownloadTask` 和在线书的 `OnlineDownload` 都能渲染。

> ⚠️ 这会**改动 `browser_page.dart`**（既有文件）。
> 需要在交接文档里标明：改的是**展示层抽象**，不改下载逻辑本体。
> 动之前先跑 `download_list_model` 相关用例，确保没打翻。

### 5.4 下载并发与节流

```
并发 3~5 章（不要更多，避免被站点封）
每章之间可选延时（部分站点有频率限制）
失败重试 2 次（复用 UrlRequest.retry）
单章失败不中断整本，记为「残缺」并在完成时提示
```

### 5.5 下载产物

```
拼接格式（交给 TxtChapterSplitter 能认出来）：

第1章 章节名
正文...

第2章 章节名
正文...
```

⚠️ **章节标题必须带「第N章」字样**，否则 `TxtChapterSplitter` 分不出来，
整本会变成一章 —— 这会让朗读时的目录功能失效。

现有 `WebToDocument._joinChapters` 已经这么做了，可复用其逻辑。

## 十二、一句话总结

> **发现页是「找书」，文档库是「读书」，书架是「存书」。**
> 三者的数据流是：书源 → 搜 → 简介 → （下载 → 本地库）或（加入 → 在线书架）或（读 → 不落盘）。
>
> 最重的不是 UI，是 **P5 的下载队列** 和 **改 `browser_page.dart` 的风险**。
