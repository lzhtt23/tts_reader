## 四、规则引擎的能力边界（**最重要的一节**）

### 4.1 实测覆盖率（194 条真实书源）

数据源：`tickmao/Novel` 的 `sources/legado/full.json`（194 条，真实有效书源）。
体检脚本：`test/real_source_coverage_test.dart`（本机有样本时自动跑）。

```
可执行（isSupported）: 186 / 194 = 96%
不可执行（缺规则/非文本）: 8

规则级求值成功分布：
  css:          2037
  xpath:          44
  css+replace:   383
  template:      234
  js:             25
  json:          453
```

### 4.2 明确不支持的三类（会抛 `UnsupportedExpression`）

| 类别 | 实测条数 | 说明 |
| --- | --- | --- |
| **JS 控制流**（`var` / `if` / `for` / 箭头函数） | 110 + 8 + 5 + 2 | 本工程不引 JS 引擎 |
| **未知函数调用**（`java.ajax` / `java.getString` 等） | 41 | 涉及 IO 或不完整语义 |
| **XPath 解析失败** | 90 | 源站 HTML 不合法，`xml` 包无法解析 |

> 💡 **为什么不引 JS 引擎**：引 `flutter_js` 代价是 APK +5~10 MB + 原生编译，
> 换来的是「规则级」约 15% 的额外覆盖。而**书源级**已经 96% 可用 ——
> 因为多数 JS 只用在某几个可选字段上，不影响主链路。
> 真要覆盖那剩下的，应当重新评估（见 §7）。

### 4.3 表达式求值器支持什么

`expression_evaluator.dart` 是手写递归下降，覆盖真实书源里的常见写法：

```
算术      page-1, (page-1)*18, 24*(page-1)
字符串    'index_'+page, baseUrl.replace('.htm','/')
三元      page-1==0 ? 'index' : 'index_'+page
成员      book.name, chapter.title
函数      java.encodeURI(key), java.timeFormat(x), String(x)
正则      baseUrl.match(/(\d+).$/)[1]
数组      key[0], result.slice(0,-3)
```

内建：`String` / `Number` / `parseInt` / `parseFloat` / `encodeURI*` /
`Math.*` / `isNaN`。
宿主：`java.encodeURI` / `java.encodeURI2` / `java.randomUUID` / `java.timeFormat`。

> ⚠️ **遇到不认识的就抛异常，绝不返回空串**。
> 静默返回空会让规则「看起来成功但结果是空的」，比直接失败更难查。

## 五、几个必须知道的实现细节（踩过的坑）

### 5.1 `{{ }}` 不一定是 JS

调研时以为 `{{ }}` 是简单变量替换，实际是 **JS 表达式**（`java.encodeURI(...)`）。
但真实数据里 388 个去重模板中 **201 个是 JSONPath**（`{{$..bid}}`）。
所以 `_expandTemplates` 先判 `$` 开头走 JSONPath，其余才走表达式求值器。

### 5.2 展开模板后不能再当 CSS

`p{{(page-1)*18}}` 展开成 `p54`，若继续送进 CSS 分析器，
`p54` 会被当「标签 p + 编号 54」→ 匹配不到 → 静默返回空。

判据在 `_looksLikeLiteralAfterExpand`：展开后不以 `@` / `$` / `/` 开头就当纯文本。

### 5.3 CSS 的 root 必须是**片段根元素**

`html_parser.parse('<a href="/x">文</a>')` 会补成
`<html><head></head><body><a…></a></body></html>`。

若拿 `documentElement`（`<html>`）当 root，
那么 `@href` 这种「只作用于当前元素」的规则会去取 `<html href>` → 空。

`CssAnalyzer.fromHtml` 因此取 **body 的唯一子元素**当 root。
这一处不改，`chapterUrl: "@href"`（最常见写法）全部失效。

### 5.4 `@href` 是纯后缀，不能按 `@` 切分

`@href` 开头就是 `@`，若按 `@` 切分会被切成空段 + `href`，
然后 `href` 又被当元素选择器 → 永远匹配不到。

`evaluate` 里对「以 `@` 开头且不含第二个 `@`」的规则走捷径，直接作用于 root。

### 5.5 索引语法的 `[-1:0]` 是「反向整个列表」

legado 的约定用法（`AnalyzeByJSoup.kt:282-292`）。
判据必须在「负数归一化」**之前**，否则 `-1` 变成 `len-1` 就再也认不出来。
反向结果**不能排序**，否则又变回正序。

### 5.6 `##` 后的正则带 `/` 定界符

真实书源大量写 `##/\d+/##`（JS 正则字面量习惯）。
不剥掉首尾 `/` 的话，`RegExp('/\\d+/')` 会去找字面的 `/123/`，永远不匹配。

### 5.7 URL 里的中文必须先编码再解析

`Uri.parse(base).resolve('/书/1')` 会抛 `Contains invalid characters`。
`UrlTemplate` 因此**先 `_encodeUrl` 再 `_resolve`**，最后再兜底编码一次。

### 5.8 `bookList` / `chapterList` 要取 **HTML 片段**

这两个字段的语义是「选出 N 个容器」，后续字段规则在容器**内部**继续选择。
所以必须拿 `outerHtml`（`RuleEngine.getElements`），不能拿 `text`。
拿 text 的话，`tag.a.0@href` 在纯文本里没有任何标签可查。

## 七、**没做的**与**已知限制**（如实交接）

### 7.1 方案 3（借声式在线阅读）**刻意未做**

`docs/v1.21.65-交接.md` 记着借声那条线刚稳定，且「引擎 stop 卡住」未修。
在线阅读若走借声，会**原样再踩那三个坑**（队列残留、清理时机、高频换状态）。

**当前做法**：`legado_read_page.dart` 一次装「当前窗 + 20 章」进 `StructuredDocument`，
走正常 `loadDocument`。翻过窗口就重装。

- 代价：不预读太远
- 好处：**完全不碰借声/换源语义**，不动音频焦点

### 7.2 已知限制

| 限制 | 影响 | 能否修 |
| --- | --- | --- |
| 不执行 JS 控制流 | 约 10% 的规则字段失败 | 需引 JS 引擎 |
| XPath 依赖 XML 合法性 | 源站 HTML 不规范时失败（90 条规则） | 需容错解析器 |
| GBK 解码需外部钩子 | 未设置时中文站点乱码 | 可接 `enough_convert` |
| `sourceUrls` 订阅索引 | 已实现，有 3 层深度上限 | — |
| 18+ 过滤 | **未实现**（legado 有 `18PlusList.txt`） | 需要一份域名表 |
| 音频/图片类书源 | 只支持 `bookSourceType == 0`（文本） | 需另做渲染路径 |

### 7.3 GBK 钩子怎么接

`SourceHttpClient.gbkDecoder` 是个静态钩子，默认 null
（此时退化为 UTF-8 宽松解码，不抛异常）。

工程已有 `enough_convert` 依赖，要接的话在启动时赋值：

```dart
SourceHttpClient.gbkDecoder = (List<int> bytes) => gbk.decode(bytes);
```

**本轮没接**：因为不确定 `enough_convert` 的 API 在 isolate 外能否直接用，
且没测过真实 GBK 站点。接之前应该先拿一个 GBK 站点验证。
